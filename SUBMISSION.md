# Комплект для проверки

## Сборка
JDK из Android Studio, Android SDK 37, NDK 28.2.13676358, CMake 3.22.1.
`gradlew :app:assembleRelease -PdemoSigning=true`
Результат: app/build/outputs/apk/release/app-release.apk (arm64).
demoSigning использует debug-ключ текущего компьютера; это подпись демонстрационного APK,
не ключ публикации в магазине. Без параметра релиз остаётся неподписанным.

При первой сборке необходима сеть; последующая сборка использует кэш. Веса встроены в APK.
При наличии локального комплекта можно передать -PmodelCacheDir=<каталог>; SHA-256 проверяется.
Для слабого телефона: -PasrModel=zipformer-ru. Качество новой конфигурации проверять отдельно.

## Приёмка
1. Установить APK, включить авиарежим и выключить Wi-Fi.
2. Импортировать WAV, затем MP3. Дождаться этапов моделей, PCM, диаризации, ASR и LLM.
3. Проверить возврат ID в A–B–A и временные границы.
4. Прослушать реплику; изменить текст; повторно распознать выбранную реплику.
5. Экспортировать JSON и открыть обычным JSON-парсером.
6. Отменить второй экспорт: результат должен остаться на экране.
7. Повторить с тишиной и повреждённым файлом.
8. Снять WER/RTF на трёх вручную размеченных записях; отметить модель устройства и холодный запуск.
9. Записать видео этого сценария. Прежнее видео отдельной LLM не заменяет полный сценарий.

## Ограничения
Одновременные голоса не разделяются: в перекрытии сохраняется один голос.
Диаризация не прерывается посередине нативного вызова.
Повторная обработка фрагмента декодирует весь исходный файл, но распознаёт только выбранный интервал.
Ручные правки не пересчитывают исторические показатели первоначального прогона.
Для длинных текстов и при превышении бюджета LLM остаётся исходный текст ASR.
GPU/NPU-ускорение не реализовано; нативные модели работают на CPU.

Не объявлять аппаратные результаты и видео готовыми до фактической проверки.
