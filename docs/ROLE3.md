# Роль №3: LLM, интеграция и проверка

## Что подключено

Общий APK выполняет импорт → диаризацию → ASR → Qwen2.5-0.5B-Instruct через llama.cpp → экран → JSON.
LLM запускается на рабочем потоке после освобождения native-сессий ASR и диаризации.
Один DTO используется всеми этапами. Ответ LLM применяется по внутреннему ID только после
строгой проверки JSON и последовательности слов, чисел и символов; speaker_id и время берутся из ASR.
При отклонении ответа остаётся исходный текст, экран показывает предупреждение.
Время LLM входит в RTF на экране. Установка ASR-весов учитывается отдельно;
проверка/установка GGUF пока входит во время этапа LLM.

«Экспорт JSON» использует CreateDocument, UTF-8 и четыре поля из брифа. При отмене или
ошибке записи результат остаётся на экране. Экспорт фиксирует снимок результата до открытия
системного окна. Ручное редактирование текста и speaker_id меняет и экран, и следующий экспорт.
«Распознать фрагмент заново» повторно декодирует исходный файл, но запускает ASR и LLM только
для выбранного интервала; абсолютное время и ID сохраняются. При сбое остаётся прежний результат.
При этом полный RTF на экране относится к первоначальному прогону, время повторения показывается отдельно.

[Образец JSON](../evaluation/example-export.json) использует демонстрационный текст и условные времена,
не является результатом замера на записи.

## Воспроизводимая сборка

Нужны Python 3.11+, Git, JDK из Android Studio, SDK 37, NDK 28.2.13676358, CMake 3.22.1.
Из корня репозитория:

```powershell
./tools/setup_llama.ps1
python tools/prepare_model.py --assets
./gradlew.bat :app:testDebugUnitTest :app:lintDebug -PllmAbi=arm64-v8a
./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest -PllmAbi=arm64-v8a
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
```

Debug APK подписан отладочным ключом и устанавливается. Для публичного релиза нужен отдельный
ключ команды. APK включает GGUF и выбранные ASR-веса; интернет требуется компьютеру при первой
сборке, приложению разрешение INTERNET не выдано. Веса проверяются по SHA-256.
Для слабого устройства можно собрать `-PasrModel=zipformer-ru`; это отдельная конфигурация,
её результаты нельзя смешивать с замерами GigaAM.

## Проверка на устройстве

```powershell
adb shell am instrument -w -e class com.example.hex.llm.RealLlmTest com.hex.stenographer.test/androidx.test.runner.AndroidJUnitRunner
# После установки приложения: поместить согласованный тестовый MP3 в эту папку.
adb shell mkdir -p /sdcard/Android/data/com.hex.stenographer/files
adb push test-audio/test1.mp3 /sdcard/Android/data/com.hex.stenographer/files/test1.mp3
adb shell am instrument -w -e class com.hex.stenographer.eval.IntegratedPipelineTest -e audio test1.mp3 com.hex.stenographer.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.hex.stenographer.eval.IntegratedPipelineTest -e audio test1.mp3 -e rumble true com.hex.stenographer.test/androidx.test.runner.AndroidJUnitRunner
adb exec-out run-as com.hex.stenographer cat files/integrated-baseline-evidence.json
adb exec-out run-as com.hex.stenographer cat files/integrated-rumble-evidence.json
```

Сквозной тест проверяет реальный инференс, сохранение слов, speaker_id и времени, валидность JSON.
Он не заменяет проверку интерфейса CreateDocument. Для неё: выбрать файл → обработать →
экспортировать → открыть JSON; повторить с отменой сохранения и редактированием одной реплики.

## Шум, перебивания и наложение

Фильтр низкочастотного гула отключён по умолчанию. Это Butterworth high-pass 70 Гц,
работающий на месте без удаления сэмплов и изменения шкалы времени. Он подавляет DC и гул,
но не отделяет голоса и не подавляет произвольный широкополосный шум. Пользователь может
сравнить обработку с фильтром и без него; улучшение WER/DER требует размеченного эталона.

Исправлена потеря коротких вложенных реплик: вложенная короткая реплика получает собственный интервал, после её конца прежний говорящий
может продолжить. Переходное перекрытие двух продолжающихся реплик делится по середине. На пользовательском тесте
второй участник присутствовал в сыром выводе модели, но полностью удалялся прежним правилом
«побеждает длинный сегмент». `OverlapPolicy.LongestSegment` оставлен для сравнения с базой.
Полноценное разделение одновременной речи не реализовано: в перекрытии по-прежнему один
активный интервал. Новый алгоритм не извлекает оба голоса из смеси и не исправляет ошибочные
кластеры самой модели. Для этого нужен отдельный локальный этап separation/overlap-aware recognition.
Изменение порога кластеризации вслепую способно объединить разных людей; порог 0.85 сохранён.
Для GigaAM ASR получает объединённые речевые участки, а не отдельные обрезки каждого говорящего.
Слова восстанавливаются по токенам CTC и целиком назначаются говорящему с максимальным пересечением
по времени. Это устраняет разрез внутри слова на смене говорящего. Очистка повторов выполняется после
назначения слов. При отсутствии или несовместимости токенов остаётся прежняя обработка по сегментам;
сквозной тест записывает `word_alignment`. Метки CTC приблизительны и не исправляют неверную кластеризацию.
Короткие отдельные речевые участки менее 250 мс по-прежнему отсекаются, длинные режутся у паузы
с пределом 25 секунд (при отсутствии паузы возможен разрез слова). Аппаратное ускорение GPU/NPU не включено.

## Приёмка и сдача

Для трёх записей A/B/C сохранять: файл, длительность, устройство/Android, SHA сборки и весов,
WER, DER, RTF, времена этапов, ошибки границ и экспорт. Если нет ручного эталона, писать
«не измерено», а не выводить качество из количества распознанных реплик.
Старые числа из README относятся к ASR/диаризации на эмуляторе без LLM.

Результаты реальных записей и ограничения приёмки: [VALIDATION.md](VALIDATION.md).
Авиарежим не включается: пользователь раздаёт интернет с телефона. Проверка без сетевого разрешения
приложения выполнена, полная приёмка в авиарежиме остаётся отдельным пунктом.
Пользовательские записи, их расшифровки и видео экрана не публикуются автоматически в Git.
